# 既存研究データを外部へ移す保存方針の追補

2026-10-08の「計画を継続する前に、コアなコードや文書は残し、容量が大きいものや外部に移動して問題ないものを選定して移動する」という指示に対応する。

## 移動対象と内蔵に残すもの

既存の参照・生成音声、解析配列、取得データセット、音声コーパスのアーカイブ、取得wheel、大容量の研究用重みとモデルキャッシュを対象とする。選定済み一覧は `research/storage-migrations/2026-10-08-v1/manifest.sqlite`、選定基準と容量は同ディレクトリの `plan.json` に保存する。

コード、Markdown等の文書、JSON・CSVの設定・評価結果・来歴、予算台帳、封印記録、仮想環境、展開済み依存ライブラリ、Webの実行環境は内蔵に残す。小容量の最終共有モデルと `htsvoice`、Git追跡ファイル、既存の外部参照リンクも移動しない。ディレクトリ全体を外部へのリンクに置き換えない。

今回の指示は、2026-10-06追補の「既存の封印済みデータや途中の保存済み波形を移動しない」という制約を、**内容・元の論理パス・封印を保持した保存場所の変更**に限って更新する。科学的な結果、契約、判定、過去の費用を変更する承認ではない。旧追補・予算の文書と承認hashは変更しない。

## 移動方式

承認済みメディア `/Volumes/CCCOMA_X64FRE_JA-JP_DV9`、UUID `B7863180-5738-36A9-BAEF-7CB3008381B3` の専用領域 `voice-simulator-data/` を使う。

- 包括サイクルのデータは既存の `arc-20261004-v1/` 以下へ移し、`StorageBudget` の位置・hash一覧にも登録する。
- それ以外の既存資料は `repository-data-20261008-v1/` 以下へ、リポジトリ内の相対配置を保って移す。
- 各ファイルを排他的にコピーし、書込完了・読み直しによるSHA-256一致を確認してから、元ファイルを同じパスのシンボリックリンクへ原子的に置換する。変更された元ファイル、既存の移動先、破損したコピーを検出した場合は元データを保持して停止する。
- メディアのマウント・識別marker・書込属性を確認する。別媒体、取り外し、容量不足で内蔵へ自動フォールバックしない。
- 移動元のサイズ・mtime・inode、移動先の実際のmtimeとSHA-256、各処理段階を内蔵の移動台帳へ保存する。媒体間のmtime精度差は、保存場所の変更記録として既存位置台帳へ反映する。

研究の生成・評価ジョブがない状態で、包括サイクルのロックを取得して実施する。包括サイクルの既存論理容量、生成・評価・学習等の回数、各campaignの終了状態と封印は維持する。対象データの外部へのコピーと位置台帳の更新費用、移動・監査時間は既存包括台帳に加算し、消費済み分をリセットしない。

包括サイクル外の移動量・全ファイルの件数・実空き容量は移動台帳に別途記録する。外部の実空き容量は移動分だけ減るため、研究再開時には固定された承認上限に加え実空き容量も必ず確認する。今回の移動で時間・生成・取得・金銭等の研究上限は増やさない。

## 検証と再開

全移動ファイルのリンク先とSHA-256、既存封印記録、包括サイクルの論理台帳・外部位置台帳を照合する。元のパスを使った音声・配列・モデルヘッダーの読取も確認する。結果は `research/storage-migrations/2026-10-08-v1/result.json` に残す。

研究の独立性試験では、元の参照パスに加え、専用外部領域全体のデータ読取を禁止する。外部のデータが別パスで読める状態を、独立性の合格へ読み替えない。既存の科学的封印は保存し、今後の隔離試験は現在の物理保存先に適用する。

この移動自体は新しい研究campaignの開始や品質達成ではない。研究の再開点は最新の `control/state.json` のチェックポイントを引き継ぐ。
