## 2. 最終方式と研究用ニューラルの境界

最終経路は、文章・音素、前後の音素特徴、モーラ・アクセント・句位置、指定F0・速度・声質から制御を計算し、DSP、ソース・フィルタ、HMM、規則、回帰、決定木、スプライン、物理・調音モデル等で生成する。共有HTSモデルによる現在の基準を使いつつ、必要な要素だけを比較・拡張する。

研究中は、日本語ニューラル教師、制御予測、逆推定、代理モデル、最適化、評価を利用できる。教師の導入時にはコード・重み・声・出力の利用条件、由来、ローカル実行費を確認し、使えない候補は理由付きで記録する。旧計画の文献と初期案は背景資料として保持し、導入済み・有効性確認済みと読み替えない。

最終実行時に教師音声、録音断片、SSL特徴、話者埋め込み、発話ID、保存済みの発話別スペクトル・高密度軌跡・波形検索を必要としない。学習発話数に比例して検索資料を増やす方式も採用しない。ネットワークの重みを数式やCコードへ転記しただけでは、ニューラル除去を達成したことにしない。

ニューラル経由の実験には、同じ資料・比較可能な実生成費で直接非ニューラル学習を行う対照を置く。現在の絶対F0実験は、教師・ニューラル・fitを使わない直接制御の比較である。将来、蒸留を再開する場合は、native、直接非ニューラル、研究用ニューラル、非ニューラル学生を同じ実レンダラーで比較する。

教師パラメータの誤差や代理モデル上の改善だけで採択しない。必ず実際の非ニューラル波形で、内容、制御、時間構造、安定性、未知入力への一般化と移行損失を検査する。参照からF0・時計を与えた再合成条件と、文章から予測した最終方式の成績は分ける。

## 3. 直近の実行順序

### 3.1 再開前の確認

1. Gitのブランチ・upstream・origin・未コミットを確認し、他の作業の変更と今回の変更を区別する。台帳、稼働ジョブ、媒体識別、実空き容量、外部位置索引を確認する。
2. `StorageBudget` で同じサイクルを再開し、論理在庫と外部SHA-256を照合する。媒体の取り違え、未完了保存、未登録ファイル、台帳との不一致を検出したら科学処理を始めない。
3. 直近の終了集計・封印を確認し、新候補16文について旧開発・選別・監査の入力履歴との非衝突を検査する。保護最終確認の本文は読まず、既存の照合用索引等で境界を守る。
4. 次の比較、隔離生成、二ASR、失敗再試行、報告・監査までを残予算と実容量で完了できるか見積もる。一時領域が必要な入口は、第5節の管理を先に備える。
5. 新規出力前に、入力・コード・モデル・対照・正規化・ゲート・費用上限を新契約に固定する。準備完了をまとまったGitの節目とする。

### 3.2 絶対F0校正の比較

問いは「文章から計算したnative LF0の絶対水準を指定Hzに合わせ、内容と相対輪郭を保ったまま、実波形でも指定に応答できるか」とする。旧訓練native80件では入力220に対するDIO中央値が約353.6Hzだったという既存診断が動機であり、新しい独立品質証拠ではない。

有声LF0に `log(指定Hz) − median(native有声LF0)` を一律に加える。指定値がnativeの駆動中央値と同値なら、準備コードのゼロ補正経路を使う。有声mask・無声sentinel、相対LF0輪郭、状態継続長、MCP、LPF、MSD、voice、設定、固定利得は保持する。文章ごとにその場で生成したnative列を使い、保存軌跡・教師・発話lookupを参照しない。

|項目|生成前に固定する案|
|---|---|
|入力|新候補16文。短文8・長文8。衝突を検出した場合は出力前に新しい入力版を固定|
|条件|neutral: 220Hz・速度1.0、higher: 280Hz・速度1.15|
|方式|native / calibratedの2方式。時間・音響フィルタ側を同時に最適化しない|
|比較出力|16文×2条件×2方式＝64件|
|独立性|64件すべてについて通常/隔離の生成64組＝128生成。別にCLI4件|
|測定・評価の見積もり|正弦fixture最大4生成、ASR最大128評価、DSP最大400。教師・fit・逆推定・取得は0|
|個別上限|4時間、500,000,000 bytes、render300、DSP600、AI200、setup50、audit50。teacher/train/inverse/downloadは0|

ゲートは出力前に次の内容を固定し、初出力後の係数探索やしきい値調整をしない。

- 工学: 全件E0合格。上記の不変量を確認し、相対LF0輪郭の絶対公差は `2e-15`。通常/隔離全64組とCLI4件で波形hashが一致する。
- ピッチ: 実波形のDIO中央値と独立なACF全体測定が、ともに指定値から1半音以内。ACF信頼度は0.6以上。nativeで固定した有声音素支持が3以上あり、候補で固定支持を欠落しない。欠測・信頼性不足の測定は不通過とし、分母から除外しない。
- 内容: 固定した正規化で二ASRを使う。各認識器の33群（both/neutral/higher × all/short/long/8系列）すべてで誤り数がnative以下。欠測は不通過。総誤り数だけの改善で系列の悪化を相殺しない。

1半音・0.6・相対形状公差は、この比較の工学的な事前設計値である。自然さや日本語全般への品質保証値ではない。旧時間実験の220/280指定をさかのぼって絶対Hz保証へ変更しない。

実行順は、登録・入力照合・必要なfixture確認 → 64比較 → 通常/隔離64組・CLI → 二ASR → 集計・費用監査・封印・セッション終了。保存済み出力とジョブ記録を照合し、途中再開では未実施分だけを行う。出力を都合よく差し替える再実行はしない。

|---|---|
|リポジトリ・内蔵|コアコード、文書、設定、契約、集計、hash・来歴、予算・ジョブ台帳、ローカル索引、実行環境、小容量の最終共有モデル|
|外部 `arc-20261004-v1/`|包括サイクルの大容量音声・解析配列・研究用重み・取得物。`StorageBudget` の論理パス・位置・hash登録で管理|
|外部 `repository-data-20261008-v1/`|今回移動したサイクル外の既存データ。元の相対配置と移動台帳を維持|
|外部の専用作業領域|事前に一時用途と定めた処理用ファイル・新規キャッシュ。第5節の予約と削除管理が備わった場合だけ使用|

既存移動の方針は[2026-10-08追補](repository-data-storage-amendment-2026-10-08.md)による。移動は内容と科学的封印を保った保存場所の変更である。ディレクトリ全体をリンクにせず、検証済みのファイル単位リンクを維持する。今後さらに移す場合も、コピー・読み直しSHA-256一致・原子的なリンク置換・位置台帳照合を行う。メディア内の他用途ファイル、旧証拠、共有環境を整理対象にしない。

大容量保存は `StorageBudget.write` / `write_data` / `external_output` を通す。自動振り分けされない大きなJSONやキャッシュも明示的に外部へ送る。未登録の実体を外部へ直接書き、台帳から見えなくする方法は使わない。`external_output` の処理中に別のサイクルファイルを保存しないという既存排他条件も守る。

取り外し、UUID・marker不一致、読取専用、容量不足、hash不一致では保存を停止し、内蔵やシステム一時領域へ代替しない。論理保存枠だけでなく、媒体の実空きと予約・終了用余裕も確認する。サイクル外の21GB規模の移動データ等も実空きを消費しており、承認枠が余っていても媒体に収まるとは限らない。

独立性試験では、元の参照パスに加え、外部専用領域の参照・教師・研究データ実体も読取禁止にする。例外は、必要な共有ランタイム資産、識別marker、当該生成の出力・一時領域に限って明示する。外部ルート全体の読取を許可しない。リンク解決後の物理パスでも禁止が効くことを確認する。

Gitは外部データのバックアップを代替しない。無視対象の生データと再開に必要なローカルSQLite索引は、hash・移動一覧とともに別途保持する。別媒体への複製は必要量を見積もってから行い、予算に計上する。

## 5. 一時ファイル・キャッシュの管理

既定の `/private/tmp/`、`/tmp/`、OSの一時ディレクトリは極力使わない。短い処理はメモリ内で完結させ、ファイルが必要な処理では外部専用ルートの `work/arc-20261004-v1/<campaign>/<run>/` 等を使う。これは今後整備する作業領域の案であり、現在の保存APIが任意の一時ディレクトリを自動管理できるという意味ではない。

現行 `StorageBudget` は登録した成果物を管理し、`arc-20261004-v1/` 内の未登録ファイルを拒否する。任意の子プロセスが複数ファイルを作る用途には、所有manifest、事前予約、照合、削除記録を共有台帳へつなぐ小さな管理入口を先に実装・検証する。別の `work/` ディレクトリへ出す場合も、そのピーク・保存・累積書込・時間を同じ予算から課す。凍結した科学コードや既存契約を変更して回避しない。

一時領域が必要なジョブは、次を満たしてから実行する。

1. 作成前に所有者、用途、ジョブID、実パス、最大bytes、保存期限・削除条件をmanifestに記録し、ピーク容量と累積書込を予約する。唯一の再開情報や最終証拠を一時ファイルにしない。
2. 媒体を確認して専用の一意な作業ディレクトリを作る。対応するツールでは子プロセス起動・ライブラリ初期化前に `TMPDIR` / `TMP` / `TEMP` と必要なキャッシュ先を明示する。実パスを検査し、共有データや他ジョブへ逸脱させない。
3. 中間ファイルは不要になった時点で削除し、残りは成功・失敗とも `try/finally` 等で後始末する。子プロセスを終了・待機し、ファイルを閉じてから削除する。
4. 削除は自分のmanifestに登録した一時ファイルに限定する。入力や成果物のリンク先、旧封印、他作業のファイルを削除しない。証拠として残す必要が生じたものは、消去前に正式成果として保存・登録する。
5. 終了時に一時領域の残存を照合し、削除件数・bytes・失敗・保留を記録する。残存量は照合後に更新するが、消費済み時間・回数・取得量・累積書込は戻さない。

媒体取り外し、プロセス強制終了等で削除できなかった場合は、未完了の掃除を記録し、同じ媒体を再確認して次回の新規作業前に回収する。削除できなかったのに完了と記録しない。専用作業入口には正常終了、途中失敗、予約超過、再開時の残存処理の意味のある検証を備える。

ツールの制約によりシステム一時領域が不可避な場合に限り、必要最小限のサイズ・期間で一意な自分専用のパスを作り、用途を記録する。不要になった時点で必ずそのファイルを削除し、最後に不存在を確認する。`/tmp` の実体が `/private/tmp` になることも踏まえて実パスを記録する。共有一時領域の一括削除はしない。大容量データや外部停止時の代替保存には使わない。

既存の共有環境・モデルキャッシュ、Git無視対象、保存済みのASR個票は、それだけで一時ファイルとは判断しない。今回作成した不要な一時ファイルだけを掃除する。

通常campaignは4時間・2GB以内。開始前の理由付き配分に限り最大8時間・4GB、通常回数枠の2倍までを使えるが、開始済みcampaignの上限を事後に増やさない。絶対F0には第3節の小さい個別上限を適用する。

計画・調査・実装・管理・Git保存・生成・評価・監査・報告の実稼働も、研究実行中は時間へ計上する。準備、一時I/O、依存導入、失敗・途中出力、再試行、移動・位置索引更新も共有台帳から課す。再開、ID変更、外部移動、削除、commitによって費用をリセットしない。

技術障害の再試行は1ジョブ最大2回、campaign計10回まで。品質不合格を技術障害として無制限に再試行しない。研究計算の同時ジョブは最大2、教師推論・学習は最大1、合計RAM目安8GB。70%消費時に配分を見直し、85%以降は経路追加を避け、残る比較・監査・終了へ重点を移す。

内蔵実空き20GB未満、外部の実空き不足、包括・個別上限到達、台帳・媒体不整合では新しい科学処理を開始しない。残額内で可能な記録・安全な終了を行う。上限に達した場合は予算終了として閉じ、品質達成とはしない。媒体停止からの再開は検証して同じ消費を引き継ぐ。

## 7. 評価と全体完了

評価は次の証拠を分けて報告する。

- 工学: E0、数値安定性、指定範囲、再実行、実時間・メモリ、依存関係、保存・隔離の検査。
- 内容: 自然参照・教師にも同じ正規化とASRを適用し、探索に使わない別方式で監査する。系列・文脈・速度別の悪化、欠測、共通基盤による証拠の重複を残す。
- 制御・音響: F0、有声/無声、継続長、VOT、遷移、帯域雑音、複数時間解像度のスペクトル。整列が必要な距離は再合成条件に限定する。
- 蒸留: 同じ実レンダラーで教師制御、学生、直接非ニューラルを比較し、移行時の損失とモデル複雑さを記録する。
- 生成の独立性: 未知入力を通常/隔離で生成し、参照・教師・ニューラル重み・ネットワーク・保存軌跡がなくても成立することを検査する。
- 知覚: 公開評点等で確認できた日本語・非ニューラル音声の適用範囲だけを合否に使う。未資格のUTMOS、学習時の判別器、教師の高スコアは診断にとどめる。

主要指標、非劣性幅、保護条件、多重性、欠測処理は再現性と開発資料に基づいて選別前に固定する。新しい試聴回答を通常の実験開始・次分岐の必須条件にしない。資格が不足しても有効な内容・音響・制御研究は続ける。

最終P5には、実非ニューラル生成での改善、内容・工学・独立性の保護、日本語で有効な知覚資格、選別に未使用の独立最終確認がすべて必要である。最終bundleは固定サイズの共有モデルと生成コードで未知入力を処理し、教師・参照・ニューラル推論・発話lookupを含まないことを監査する。

P5判定器は資格不足、欠測、保護条件悪化、確認集合の再利用を拒否し、有効な独立証拠を受理できる両経路を実装・検証する。人工fixtureで判定器が動いたことを実音声品質の証明にしない。確認資料を一度選別へ使用した場合は、以後その比較を診断と記録し、独立確認へ戻さない。

個別campaignの終了、容量改善、保存基盤の完成、Git保存、予算終了は全体品質の達成と区別する。品質未達でも承認枠内に有効な経路が残る間は、結果から次を選び実行する。

## 8. 未コミットをためないGit運用

ユーザーの2026-10-08指示に基づき、研究の成果を適度な単位・タイミングで **commitし、push originする**。通常の承認済み変更を保存するたびに再承認を求めない。開始時に現在のブランチ、origin、upstream、ローカル/リモートの差と既存変更を確認する。本書作成時は `main` / `origin/main`、originは `https://github.com/dolphilia/voice-simulator.git`。

保存単位は、登録・実装・必要な検証がそろった変更、実験終了の集計と判断、文書改訂など、後から内容を説明・確認できるまとまりとする。約60分の作業継続、またはコード・文書等が約30ファイル変わった時点を未コミット量の見直し目安にし、ジョブ境界で保存する。これは壊れた途中実装や生成ファイルを機械的にcommitする期限ではない。長い処理中は完成部分と再開情報を保存し、稼働中の台帳の不整合な断面をcommitしない。

各節目で次の順に行う。

1. `git status` と差分を確認し、今回扱ったファイルだけを名前でstageする。他の作業の変更を巻き込まず、無条件の `git add .` は使わない。
2. 変更に見合う必要な検証と `git diff --check`、stage済み差分の確認を行う。意味のあるコード・文書・契約・集計・共有係数・hash一覧を残す。
3. 音声、巨大配列・重み、ASR個票、高密度軌跡、端末固有SQLite、一時ファイル、外部実体リンク、資格情報が不要に追跡されていないか確認する。`.gitignore` は出力用途に限定し、JSONや `results/` 全体を隠さない。既に追跡されている不要物は、実体を残した追跡解除を個別に検討する。
4. 内容と結果が分かるcommitを作り、現在の作業ブランチをoriginへ通常pushする。ブランチと宛先を確認して `git push origin HEAD:<作業ブランチ>` 等を使い、成功後にローカルHEADとリモート先端の一致を確認する。
5. commit ID、push結果、残る変更と次の処理を進捗へ記録する。push後の記録だけで小さな未コミットを連鎖させず、次の自然な保存単位へまとめる。

認証・通信・リモート更新でpushに失敗した場合は、commitを残し、原因・未送信commit・再試行点を記録する。差分を確認して通常の安全な同期を行い、force push、共有履歴の破壊、他作業のresetを行わない。未送信変更が増え続ける場合は新しい大きな変更への着手を抑えて、同期の回復を先に扱う。

Git無視はデータ削除でもバックアップ完了でもない。`control/state.json` と `control/jobs.jsonl` は整合した節目で保持し、ローカル索引と外部生データは第4節の保存を維持する。旧承認文書・封印・契約を後から書き換えて新計画に合わせない。

## 9. 記録・継続・終了の引き継ぎ

各節目の追記版に、問い、変更と因果要因、実行入口、入力・モデル・コードhash、対照、ゲート、結果・欠測・悪化群、不採択理由、全費用・残予算、稼働/未完了ジョブ、一時領域の削除状況、Git保存状況、未達条件、次の具体的操作を残す。文脈やターンが切り替わっても、この記録から継続する。
