# 計画書: 試聴待ちで停止しない母音自動探索 v1

作成日: 2026-09-13  
状態: A0〜A5完了。A3は特徴空間被覆へ目的改訂し64設定・192音、A4は8候補・240音を完了。A5試聴packageは `not_queued` で凍結済み  
対象: `/a/`・B9近傍の定常部を起点とする明示DSP探索  
設計根拠: [自律的な合成研究への転換](../note/autonomous-synthesis-research-approach.md)、[評価・最適化案のレビュー](../note/speech-synthesis-evaluation-and-optimization-review.md)

## 1. 決定

既存の[一般化計画](synthetic-vowel-generalization-plan.md)は、B9/G40を一人の試聴者内で再確認し、F0・母音・attackへ順に広げる**採用確認系**として維持する。ただし、その試聴完了を新しい生成候補の調査・生成・測定の開始条件にはしない。

新たに、次の**開発探索系**を独立して進める。

1. B9近傍の明示DSPパラメータを有限範囲で動かす。
2. 実現した音を既存の比較評価基盤で測り、固定回帰と感度解析を行う。
3. 単一総合点を作らず、制約を満たすPareto候補と異なる特徴領域の候補を残す。
4. 人の回答を待つ間も、凍結したcampaign単位で探索と失敗解析を完了する。
5. 人が試聴できる時だけ、代表4候補を含む小さいブラインド試聴へ接続する。

この計画は、音響指標の改善を人声らしさの改善とみなさない。自動探索の成果は「候補と残差の地図」であり、知覚的な採用には別の試聴証拠を必要とする。

## 2. 既存計画との境界

| 系 | 役割 | 待機の扱い | 結果の意味 |
|---|---|---|---|
| V: 一般化・採用確認 | B9/G40の別日反復、F0、5母音、attack scaling | 既存の順序と24時間規則を維持 | 指定試聴者・条件内の知覚確認 |
| R: 本計画の開発探索 | 生成、測定、感度、探索、頑健性、候補選別 | 試聴待ちを開始条件にしない | 工学的成立、測定上の残差、候補多様性 |
| I: 独立音声合成E0/P1 | 過去資産に依存しない別方式の成立性確認 | 固有の証拠契約に従う | 独立モデルの限定的な検証 |

- Vの凍結済み音声、hash、回答、合否は変更しない。
- Rの未試聴候補をVの `listener-qualified` や `release` と呼ばない。
- IのE0/P1へB9を初期値として持ち込まない。Iの固定出力を将来比較する場合は、I完了後に新しい比較campaignを作り、元のE0/P1結果を書き換えない。
- Rで得た結果をVへ反映するのは、凍結試聴と未使用seedによる確認後だけとする。

## 3. v1の範囲

### 3.1 対象

- 母音: `/a/`
- 平均F0: 220 Hzを探索条件とし、160/220/300 Hzを後段の頑健性条件とする
- 主対象: 定常部の音源と低周波変動
- 固定するもの: B9の声道フォルマント、帯域幅、出力レベル、基本の合成構造
- 探索候補: spectral tilt cutoff、F0変動量、振幅変動量、制御帯域、F0・振幅相関
- 生成物: 録音断片や生成AIを含まない、明示DSPからの新規波形

最初から音源と声道を同時に自由化しない。v1では声道を固定して音源側を調べる。声道側の探索は、音源側を固定した別campaignで行う。

### 3.2 v1で行わないこと

- ASR、forced alignment、学習済みMOSを必須依存にすること
- 参照録音の波形、密なスペクトル包絡、フレームごとの軌跡を生成器へコピーすること
- 未校正の特徴量分布や単一スカラーで、人声性・自然さを自動認定すること
- 本格的なMAP-Elites、CMA-ES、ベイズ最適化、微分可能DSPの先行導入
- 他母音、CV、単語、文章を実装完了条件にすること
- Web既定音や既存release manifestの変更

## 4. 証拠と状態の契約

候補の採用状態 `draft → signal-qualified → listener-qualified → release` は維持し、別に次の四領域を保存する。

| 領域 | 必須内容 |
|---|---|
| `engineering_checks` | 有限値、clipping、DC、端点、指定F0/RMS、フィルタ安定性、再生成一致 |
| `proxy_results` | 指標別の値、category、評価器version、coverage、confidence、欠損理由、参照群 |
| `robustness_results` | seed、F0、長さ、sample rateごとの実現値と失敗率 |
| `listening_status` | `not_queued`、`queued`、`answered_exploratory`、`confirmation_complete` |

候補には少なくとも `campaign_id`、`candidate_id`、親候補、生成器version、設定hash、seed、WAV hash、参照・測定version、作成理由を持たせる。同じIDの設定や音声を上書きしない。

## 6. 音響目標仕様

`acoustic-targets-v1.json` は少なくとも次を持つ。

| フィールド | 意味 |
|---|---|
| `target_id` | 不変の目標ID |
| `vowel`、`f0_condition_hz`、`segment_kind` | 適用条件 |
| `reference_group_id` | 参照群。個別録音と混同しない |
| `feature`、`unit` | 測る量と単位 |
| `target_interval` | 凍結参照から得た範囲。点目標に限定しない |
| `provenance` | 入力hash、選定規則、集計法、ライセンス上の利用範囲 |
| `estimator` | 実装・profile・version・測定窓 |
| `uncertainty` | 話者差、短時間推定、推定器の既知誤差 |
| `missing_policy` | `unavailable`、`unsupported`、hard failureの区別 |
| `role` | `constraint` または `diagnostic` |

目標値は既存文書の例示値から転記しない。A0で利用可能な凍結参照、既知信号fixture、既存測定のhashを照合して作る。設定フォルマント、出力スペクトルピーク、LPC推定フォルマントは別featureとして扱う。

hard constraintは信号破綻と制御不成立に限定する。参照距離、声質指標、UTAU分布への近さはdiagnosticとし、候補全滅の条件にしない。

複数参照は話者・録音条件を保持したまま個別に評価し、中央値と最悪側の両方を残す。全参照を一つの平均音へ潰さない。既存holdout結果は評価器が同じ失敗を再発していないかを見る回帰資料には使えるが、既に結果を確認済みなので新campaignの独立最終試験には使わない。

## 7. 固定回帰セット

### 7.1 smokeセット

コード変更ごとに短時間で実行し、少なくとも次を含める。

- B6、B9、G40の既存hashまたは意味的回帰
- B9のcanonical seedと既存未使用seed検証例
- 無音、clipping、DC、非有限値、極端なF0逸脱を検出する解析fixture
- `unavailable` と `unsupported` が合格数へ混入しないfixture

### 7.2 campaignセット

campaign終了時に、対応できる範囲でseed、160/220/300 Hz、0.8秒と測定用長尺、16/48 kHzを組み合わせる。未実装の条件は `unsupported`、推定失敗は `unavailable` として件数と理由を表示する。

レポートには総合合格数ではなく、条件別の実現F0/RMS、指標差、coverage、信号失敗、前versionからの回帰を載せる。この固定セットは頻繁に利用するため、独立holdoutとは呼ばない。

## 8. 実行段階

### A0: 資産台帳と契約の凍結

1. B6、B7、B9、B10、G40と既存不成立候補を台帳化する。
2. 音声hash、生成設定、seed、実現値、質問軸、回答、推論範囲を結び付ける。
3. 開発参照群、探索に使わない確認用参照、探索seed、頑健性seed、確認seedを分離する。
4. 音響目標仕様、候補schema、campaign設定、固定回帰セットを凍結する。
5. 既存設定・測定から各探索境界の出典を記録する。根拠を確保できない軸はv1から除外する。

完了条件: すべての入力にhashと用途があり、既存回答を新しい絶対評点へ推測変換していない。

### A1: adapterと回帰の実装

1. version付き生成adapterからB9を再生成する。
2. version付き測定adapterから既存feature bundleとscorecardを生成する。
3. smokeセットと変更前後レポートを実装する。
4. 同一設定・seedの再生成一致と、別seedの非同一性を検証する。

完了条件: B9の既知結果を再現し、欠損・未対応・信号破綻が別状態で出力される。

### A2: 実行費測定と感度地図

1. B9中心で各パラメータを一つずつ両方向へ動かす有限差分を行う。
2. 設定値ではなく、生成音から測った実現値の差分を保存する。
3. 指標ごとの感度、符号、非単調性、飽和、パラメータ間の交絡候補を報告する。
4. 生成・測定の1件あたり時間と保存量を測り、A3の実行上限内に収まることを確認する。

境界付近では片側差分を明示する。seed変動より小さい差を有効な感度と断定しない。目標方向へ動かせない指標は、探索不足と表現力不足の候補を分けて記録する。

完了条件: 探索する各軸に、根拠付き範囲、観測可能な作用、または除外理由がある。

### A3: 有界探索

当初の `avs-a220-v1` pilotは測定adapter修正後に `avs-a220-v1.1` となり、代理目的改訂後の正式探索は `avs-a220-search-v1` として分離した。64設定の内訳は、根拠付きanchorとHalton列による構造化32設定、同じ32評価のLatin hypercube無作為探索を対照とした。凍結済み設定の正本はA3成果物 `frozen-settings.json` とする。

- 上限64設定
- 各設定で共通3 seed
- 上限192音
- 全評価、制約違反、欠損、実行時間を保存
- 声道パラメータは固定
- 個別目的を保持し、カテゴリ横断の「人間らしさ総合点」を作らない

単一の最良値ではなく、hard constraint通過候補のPareto集合と、明るさ・変動量・周期性などの粗い特徴領域ごとの代表を残す。最適化方式の優位は、同予算のランダム対照より残差・頑健性・多様性が改善した場合にだけ報告する。

既存 `pareto_front()` は個別taskのカテゴリ比較に再利用する。複数参照・seed・条件をまとめる部分だけを薄い集約層として追加し、中央値だけでなく最悪側とcoverageを目的ベクトルへ残す。

完了条件: 上限内で探索が閉じ、候補、失敗領域、対照との差、再現手順が保存される。人声改善は結論しない。

### A4: 未使用条件での頑健性検査

A3から最大8候補を選び、探索に使っていないseedとF0で検査する。

- 最大8候補
- 候補ごとに10 unseen seed
- 160/220/300 Hz
- 上限240音
- A3と合計して最大432音

平均だけでなく、条件別失敗率、最悪値、分散、推定不能率を保存する。この結果を見て選別したseedは、後の独立確認には再利用しない。

完了条件: seed/F0依存と適用範囲が候補ごとに記録される。

### A5: 代表候補と試聴パッケージの凍結

最大4候補を次の異なる理由から選ぶ。

1. 複数目的で一貫して良い候補
2. 別のPareto端を代表する候補
3. 評価カテゴリ同士の判断が食い違う候補
4. hard constraint通過層からの層別無作為候補

同じ候補が複数枠を満たす場合は、別の特徴領域から補う。候補、B9 anchor、隠し重複を含む6比較程度のパッケージを凍結する。ただし、有効な試聴キューは同時に一つまでとし、既存の採用確認試聴と競合する場合は `not_queued` のまま保存する。

完了条件: 音声・提示・質問・乱数・hash・選定理由が固定され、人の回答なしでもcampaign報告が完結する。

実績: A4の220 Hz・未使用seed 1701から4候補とB9アンカーを選び、隠し重複を含む6提示を `avs-a220-search-v1-listening-v1` として凍結した。二択は `y/yes/n/no`、相対比較は `a/b/same/unsure` を受け付ける契約である。既存の別日反復試聴が有効なため、状態は `not_queued` とする。

### B1: 探索用の少数試聴

試聴者が都合のよい時に既存ウィザードで実施する。

- 最初に音量確認を行う。
- 必要な範囲で再生を繰り返せる。
- 母音同一性、人声同一性、artifact有無は `はい/いいえ` と `y/n` を受け付ける。
- 相対比較はA/Bに加えて `SAME` と `UNSURE` を残す。
- 条件名、選定枠、隠し重複位置を表示しない。
- 相対勝者でも絶対的な母音・人声条件を満たさなければ採用候補にしない。

この試聴は探索方向の更新用であり、releaseの最終確認ではない。回答後に評価器の選別成功、無作為枠の取りこぼし、重複一貫性を記録する。

### B2: 独立確認

探索用試聴で前進が見えた候補だけを、新しいcandidate version、未使用seed、凍結前比較規則でB9と確認する。探索用回答と確認回答を合算しない。

確認の合格範囲は一人の試聴者・テストした母音/F0/seedに限定する。一般化やreleaseはV系の契約へ接続して判断する。

## 9. 予算と停止規則

| 項目 | v1上限 |
|---|---:|
| A3設定 | 64 |
| A3生成音 | 192 |
| A4候補 | 8 |
| A4生成音 | 240 |
| A3+A4生成音 | 432 |
| 試聴候補 | 4 |
| 1探索バッチ | 約6比較 |
| 同時に回答待ちにする探索バッチ | 1 |

- 上限到達後に自動で範囲、seed、候補数、モデル構造を増やさない。
- 実行費ベンチマークで予定資源を超える場合は、設定数ではなくcampaignを停止し、測定費と保存方針を見直す。
- hard constraint通過候補がない場合は、破綻原因を分類して終了する。合格しやすい閾値へ自動変更しない。
- 2 campaign続けて試聴上の前進がない場合は、同じ探索を追加せず、損失・推定器・生成構造のどこが律速かを診断する。
- 自動指標だけが改善し試聴が悪化した場合、その指標または適用範囲を次campaignで降格し、結果を消さない。

計算時間と保存量の絶対上限は、A2の実測後、A3開始前にcampaign設定へ固定する。未測定の値をこの計画で推測して固定しない。

## 10. CLI契約

計画する操作単位は次のとおりとする。各コマンドは既存成果物を既定で上書きせず、不足前提を理由付きで拒否する。

| 操作 | 役割 |
|---|---|
| `inventory` | 既存候補、設定、音声hash、試聴証拠から台帳を構築 |
| `validate-config` | schema、参照用途、seed分離、探索境界の出典を検査 |
| `regression --suite smoke|campaign` | 固定セットを実行し、前versionとの差分を生成 |
| `sensitivity` | 有限差分、seed内変動、到達範囲、実行費を測定 |
| `run-campaign` | 凍結済み設定を有限予算で生成・測定 |
| `evaluate-campaign` | Pareto、特徴領域、失敗領域、対照差を保存 |
| `robustness` | unseen seedとF0で候補を再検査 |
| `freeze-listening` | 4候補、anchor、重複を上書き不能な試聴packageへ固定 |
| `status` | 完了段階、消費予算、不足、試聴状態、解釈範囲を表示 |

主要成果物は `ledger.jsonl`、`targets.json`、`sensitivity.json`、`evaluations.jsonl`、`pareto.json`、`failure-regions.json`、`robustness.json`、`regression-diff.json`、`campaign-report.md` とする。大きなWAVや再生成可能な図はGit管理方針に従い、manifestとhashを必ず残す。

## 11. 判定と成功指標

### 11.1 campaignの工学的完了

次をすべて満たせば、知覚未確認でもcampaignは完了できる。

- 設定上限内の全試行が完了または理由付きで失敗した。
- 入力・設定・コード・音声・測定のhashとversionが記録された。
- Pareto集合、特徴領域、失敗領域、感度、頑健性が報告された。
- `unavailable`、`unsupported`、hard failureが区別された。
- 試聴候補が凍結済み、または有効候補なしの終了理由が保存された。

### 11.2 研究運用の評価

- 人の回答待ちなしで閉じた実験単位数
- 再生成成功率、測定失敗率、実行時間、保存量
- 同予算ランダム対照に対する残差・多様性・頑健性の差
- seed/F0別のhard failure率とproxy悪化率
- 試聴1分あたりの確認済み前進候補数
- 自動上位の人声不成立率と無作為枠の取りこぼし率
- 独立確認で改善、非劣化、悪化となった割合

## 12. 実装順序と直近の作業

次の順に実装し、A0〜A2を最初の作業単位とする。

1. `autonomous-vowel-search/` の最小CLIとschemaを作る。
2. 既存候補・回答の台帳生成を実装する。
3. 生成・測定adapterを作り、B9で回帰を通す。
4. 音響目標仕様を凍結する。
5. smoke回帰と変更前後レポートを作る。
6. 有限差分の感度pilotと実行費ベンチマークを実行する。
7. 結果に基づき、根拠のある探索軸だけで `avs-a220-v1` を凍結する。
8. A3〜A5を人の介入なしで完了する。
9. 既存試聴キューとの競合がなくなった時点でB1を提示する。

最初の実装完了報告には、未試聴であること、対象が `/a/`・B9近傍に限られること、音響上の改善が人声性の改善ではないことを必ず併記する。

## 13. onsetと一般化への継続

`avs-a220-v1.1` は探索器と評価器の接続を、既知のB9定常部で検証するpilotである。代理指標と既知試聴方向の不整合を受け、A3は `avs-a220-search-v1` として特徴空間被覆へ目的を改訂した。構造化32設定と層別無作為32設定はいずれも13セルを占有し、方式間の優位は認めなかった。A4では8候補を160/220/300 Hz・各10未使用seedで検査し、240/240音が工学通過した。

一方、既存の非UTAU再監査では「開始文脈を残すと人間らしさが高い」という主仮説は、この試聴者・課題で反証されている。合成音ではG40の開始自然さに局所的な優位があるため、onsetを捨てるのではなく**主要因から副次制御へ降格**して扱う。以後は次の順で進める。

1. **`avs-onset-a220-v1.1`:** 0/40/60/80 ms × 3 seedを完了し、G40 hash、全12音の工学通過、定常部RMS不変、実現attack時間の単調応答を確認済み。40 msを副次的アンカーとして維持し、gain durationの密な追加探索は行わない。
2. **F0頑健性:** 定常部とonsetを160/220/300 Hzで測り、固定時間と周期比例を別仮説として保持する。
3. **他母音:** 音源規則を固定して声道側を母音別に調べる。母音ごとの参照範囲と推定不能率を分ける。
4. **小さい共同調整:** 音源単独・声道単独で説明できない残差が残った場合だけ、両者の範囲を狭くして調べる。

onset campaignでは、0.8秒全体の平均だけで開始差を薄めない。開始窓と定常窓を別featureとして保存し、提示用の端点fadeを自然な発声開始の証拠に使わない。自動campaignは続行できるが、試聴packageはキュー上限に従って一つずつ提示する。
