# 同じ内部列で音源・フィルタを切り分けた結果

2026-10-03。[承認された計画](../plans/source-filter-counterfactual-proposal-2026-10-03.md)を新ID `nas-source-filter-20261003-v1` で実施した。**54生成・54件のDIO＋StoneMask計測を完了。既定18波形は旧WAV、内部LF0、保存DIO列と完全一致した。元の欠損11条件のうち5はスペクトル平坦化、2はLPFを外す対照で回復したが、4は残り、新たな欠損も発生した。品質目標は未達。**

## 比較の固定と入口

旧17封印・8,574ファイルを開始・終了に照合し、旧結果・波形・モデル・計画を変更していない。元の支持域欠損11条件と対応する既定7条件の18列を固定し、開発10列・機構診断の確認8列に分けた。ASRの良し悪しで選別していない。これらは使用済み診断文であり、独立最終品質確認ではない。

対応版HTSヘッダを使うC wrapperを既存clangで構築した。Cが所有するエンジンで状態→MLPG→波形を分け、Pythonオブジェクトから内部ポインタを推測していない。基準波形は元のHTSサンプル生成入口を使う。平坦化はスペクトルのc0を保持し形状係数だけを0へ変更、単純励起はその状態から第3ストリームのLPF混合を外した。変更したPSSをC側で復元し、実際にVocoderへ渡された列を全件検査した。

各18列の元MLPG表を1度だけ保存し、3方式で配列が同一であることを確認した。状態継続長、MSD、LF0動的平均、LF0列、Vocoder設定を維持した。研究NN由来の条件も保存済み補正を使い、ニューラル推論・重み読込を実行していない。OSでネットワーク・教師・ニューラル重みへのアクセスを遮断し、生成前のネットワーク拒否と全生成後の禁止モジュール未使用を確認した。

最初の18生成が旧WAV SHA-256、内部LF0配列、保存DIO/時刻配列と完全一致し、有限・E0・内部不変を通過してから、対照36生成を開始した。全54件で有限・E0通過。通常の再生成を追加して数を増やしていない。

## 元の欠損区間の対照

DIO＋StoneMaskは70〜800Hz・5ms。固定支持域の3フレーム以上・50%以上を維持し、欠損を補間・区間削除・境界移動で救済していない。以下は元の欠損区間だけの回復状況であり、波形全体の資格ではない。

|観測|開発の欠損6条件|機構確認の欠損5条件|合計|
|---|---:|---:|---:|
|平坦化と単純励起の両方で回復|2|3|5|
|平坦化では欠け、LPFを外して回復|0|2|2|
|どちらでも元の欠損が残る|4|0|4|

平坦化で回復したのはselection-02通常NN（/a/）、unknown-10通常NN（/o/）、wave-new-04変更NN（/a/）、wave-new-05通常の直接・学生（/a/）。各候補のDIO有声数は順に3/15→15/15、2/16→16/16、0/17→13/17、6/15→15/15（直接・学生とも）だった。selection-02 NNでは検出点の内部LF0との半音絶対誤差中央値も7.877→0.155となった。他の欠損点を誤差集計から除いて合格扱いにはしていない。

LPFを外すと回復したwave-new-03通常の直接・学生の/u/は、DIO有声11/24→12/24という1フレーム差だった。残った4条件はwave-new-00通常の直接・学生・NNとwave-new-01通常NNの/u/。これらの検出点のF0誤差は平坦化・単純励起で小さくなったが、有声率の条件は満たさなかった。

回復は「スペクトルと周期性の観測経路」「励起混合と境界」という機構候補の証拠であり、測定器だけが悪い、元の音源が正しい、自然な日本語になったという証明ではない。LPFを外すことで励起の混合や波形も変わるため、単独原因の確定とは扱わない。

## 新たな欠損を含む全支持域

|方式|波形数|支持域欠損がある波形|欠損区間|E0不通過|
|---|---:|---:|---:|---:|
|元の再合成|18|11|11|0|
|スペクトル平坦化|18|8|10|0|
|単純励起|18|8|10|0|

平坦化ではwave-new-01既定のlabel9、wave-new-03の既定・直接・学生のlabel6が新たに欠けた。単純励起ではwave-new-01既定とNNのlabel9、同既定の元は通過していたlabel12も欠け、wave-new-03のlabel6も残った。元の焦点7条件の回復だけを示して対照を採択しない。平坦化・単純励起を日本語品質の候補にしていない。旧ASRや主F0-MSEを変更していない。

## 保存列で調べた時間イベント

新推定・生成なしで、保存したMLPG・MSD・状態時間とDIO列の287区間を照合した。全18列でMSD>0.5を状態継続長へ展開した有声マスクとMLPGの有声マスクが一致した。

焦点18条件のうち、/u/の9条件（候補6・既定3）は、音素24フレーム=120msのうち有声駆動が11フレーム=55ms、**45.83%**だった。状態時間は5/4/2/6/7フレームで、最初の3状態だけが有声。F0補正・平坦化・LPF除去はこの有声スケジュールを変更していない。

完全に駆動マスクを回復する測定器でも、この11/24区間は音素全体の50%条件を満たさない。これは量の違いを示す設計診断であり、旧判定を不通過から合格へ昇格させる根拠ではない。今回LPFを外して12/24となった2条件も、有声駆動を増やした結果ではない。

DIO時刻を5msの整数格子へ照合すると、浮動小数の半開区間と区間所属が異なる例が各方式72/287区間あった。ただし今回は3フレーム・50%の合否が変わる区間は0。元の浮動小数マスクと判定を保持した。

## 費用・失敗・終了

上限1時間・追加100MB・render54・AI/fit/逆推定/教師/取得0に対し、終了監査は**560.492秒・16,694,504 bytes、render54、setup4、audit4**。DIO＋StoneMaskの記録54、AI0、追加生成・再試行0、未終了プロセス0。資料・封印を含む最終値はartifact-sealに残す。

台帳の補助失敗1件は、旧pilotの同名renderer.pyがimportされた接続不備。生成前に初版と失敗記録を保存し、固有名の接続版へ変更した。ビルドを繰り返さず成功済みbinaryをhash照合して再利用し、制御・wrapper・診断条件は変更していない。有効入口はprepare-v2.pyとrun-v2.py。Cの形状・方式・非有限・NULLの負例7件、c0/LF0/LPF保持、元配列不変、支持域欠損拒否、非単調な対照を単一原因へまとめない検査を通過した。

今回の研究比較は完了して閉じた。旧採択不通過、日本語測定資格不足、未知文の内容保護、局所閉鎖・開放・摩擦・声質、非ニューラル知覚資格、独立最終品質確認は解決していない。計画全体の完了を認定しない。
