# 調査・研究・解析の総括

作成日: 2026-08-13

## 1. この文書の目的

この文書は、`voice-simulator` でこれまで行われてきた調査、研究、解析、数値実験、Web プロトタイプ実装を横断的に棚卸しし、現時点で何が分かっており、何がまだ分かっていないかを整理するものである。

単なる成果物一覧ではなく、次の観点を区別して記録する。

- 実際のコードと出力によって確認できること
- 限定された条件で成立した概念実証
- 文献から導いた仮説や設計候補
- 計画にはあるが未検証のこと
- 研究上の偏り、再現性、評価方法の不足
- 新しいプロジェクト方針のもとで優先すべき次の作業

本書は 2026-08-13 時点のリポジトリとローカル研究資産を対象とする。外部文献の内容を改めて追試・査読したものではなく、既存文書、実装、保存済み出力の整合性を精査した結果である。

## 2. 総論

このプロジェクトは、当初の「物理的な発声シミュレーター」という構想から、次のような研究開発系へ発展してきた。

1. フォルマントフィルタによる最小の母音合成
2. 多管モデルと 1D デジタル波動管による声道形状ベースの合成
3. 声門音源、摩擦音、乱流、流体力学の部分モデル
4. DWM と FDTD による 2D 音響伝搬の探索
5. UTAU 音源をリファレンスにした母音、話者差、声質、遷移、ノイズの解析
6. 生成音とリファレンス音を比較する評価ツールと反復調整
7. 解析結果を Web プロトタイプで試聴・観察するフィードバックループ

最大の成果は、方式候補を広く列挙したことだけではない。参照データを解析し、実装可能なパラメータへ変換し、生成音を評価し、Web 上で確認するところまで、一部ながら経路がつながったことである。

一方、現時点で「人間の発声に近い音声を生成できた」と総括するのは早い。成立しているのは、母音と一部の摩擦音・声質要素を対象にした探索環境である。自然発話、音素列、韻律、共調音、鼻音、破裂音、知覚評価、複数話者への一般化、高忠実度モデルとの照合は未成熟または未着手である。

## 4. これまでの発展過程

### 4.1 基盤整備と最小母音合成

初期段階では、研究用 Notebook と TypeScript/Web Audio API のプロトタイプを分離し、まず音が出て母音差を操作できる環境が作られた。

第1 Web プロトタイプは、のこぎり波と 3 バンドの Biquad フォルマントフィルタを組み合わせた source-filter 型である。これは物理的な声道そのものではないが、ピッチ、フォルマント、帯域幅、ゲイン、声道スケールの関係を即座に確認できる基準系となった。

この段階で重要だったのは、高忠実度よりも「変更したパラメータと聞こえ方の関係を観察できること」を優先した点である。この基準系は、後の UTAU 解析値、`tuned` プリセット、`brightness`、`breathiness`、子音イベントを受け入れる試聴台へ発展した。

成熟度: B から A の中間。実装とビルドは成立しているが、母音品質の正式な知覚評価はない。

### 4.2 声道形状と 1D 波動管への展開

第2プロトタイプ `tube-vocal-tract` では、声道を複数管の断面積列として表し、Kelly–Lochbaum 型の反射係数と Canvas 上の声道エディタを導入した。

この試作から、単にフォルマント値を指定するのではなく、形状から音響特性を生み出す方向へ進んだ。ただし、初期実装は同一サンプル内で全区間を更新するため、物理的な伝搬遅延が正しくなく、形状と共鳴の対応は限定的だった。この問題を明示的に認識し、第3プロトタイプ `waveguide-vocal-tract` へ移行したことは重要な進展である。

第3プロトタイプでは、次を実装した。

- ダブルバッファによる 1 セクション 1 内部サンプルの遅延
- 2 倍オーバーサンプリングと 44 セクション
- 文献由来の 16 制御点を補間した日本語 5 母音の断面積列
- 断面積依存の簡易損失
- インパルス応答と FFT ピークによるフォルマント推定
- LF 型を意図した声門音源

ただし、設計文書と実装の間には差がある。計画書に記された完全な LF 式、エネルギー保存条件を満たす `alpha` の数値解、LPC 極推定は、現行実装では簡略化されている。実装は `alpha=0` 相当の半正弦と線形復帰であり、フォルマント推定も LPC ではなく FFT ピーク検出である。したがって「LF モデル実装済み」「LPC で実測値と一致」といった強い表現は、現状では目標または近似実装として読む必要がある。

成熟度: C。実装と操作環境は存在するが、5 母音の目標フォルマントとの誤差表、解析解との比較、保存 WAV による回帰評価がない。

### 4.3 波動管の音程検証

`trombone-waveguide-simulation.ipynb` では、均一な閉端・開端管の長さを 20〜45 cm で変化させ、理論式 `f0 = c / 4L` と波動管の発振周波数を比較した。

保存された実行結果では、代表 7 点の誤差は 0.230%〜1.190% だった。管長を変えると基本周波数が理論どおり低下し、波動管の遅延が音程へ反映されることは確認できる。

一方、Notebook 本文にある「誤差 0.2〜0.4% 以内」「数セント以内」という記述より、実際の表の最大誤差 1.190% は大きい。また、検証チェックリストは未チェックのままである。したがって結論は、定性的な追従とおおむね 1% 程度の一致が確認された、という範囲に留めるのが適切である。

成熟度: B。解析解との比較がある点は強いが、誤差評価の記述を実測表に合わせて改訂する必要がある。

### 4.4 声門音源モデル

`glottal-source-models.ipynb` では、のこぎり波、Rosenberg C パルス、LF 型音源を波形、微分、スペクトル、母音合成音として比較した。`Rd` を 0.6〜2.5 で変化させ、きしみ声から気息声に相当する連続変化も試した。

得られた実務上の知見は次のとおりである。

- のこぎり波は基準信号として簡単だが、開閉の非対称性を表せない
- Rosenberg 型は低コストで、開口・閉口比を明示的に制御しやすい
- LF 型のパラメータは、声質を連続制御する統一的な入口になりうる
- 声道モデルだけでなく、励振源のスペクトル傾斜と閉鎖特性が音質を大きく左右する

ただし「LF が最も自然」とする判断は、Notebook 内の試聴上の所感であり、被験者評価や実録音との定量比較ではない。EGG、逆フィルタリング済みグロッタルフロー、公開ベンチマークとの照合も未実施である。

成熟度: B。モデル比較と可聴化は成立したが、実声帯データによる同定が必要である。

### 4.5 摩擦音と流体力学的音源

摩擦音研究は 3 段階で進んだ。

#### Phase 1: 収縮と乱流ノイズ

収縮断面積、体積速度、Reynolds 数から乱流ノイズ振幅を求め、前方腔を highpass と bandpass で近似した。保存された計算例では、`/s/`、`/ʃ/`、`/f/` の Re がそれぞれ 3885、3364、2747、母音 `/a/` が 869 となり、収縮部だけでノイズを立ち上げる構図を確認した。

#### Phase 2: 後方腔と有声摩擦音

後方腔の共鳴器と簡略グロッタルパルスを追加し、`/s/` と `/z/`、`/f/` と `/v/` のような無声・有声連続体を `voiced_ratio` で表現した。

#### Phase 3: 波動管とのハイブリッド

波動管の途中へノイズを直接注入する初期案では、摩擦音間の差が消えた。原因を調べ、壁面損失 `alpha_wall=0.30` が強すぎ、短い前方腔の Q を過度に下げていることを特定した。そこで、周期成分は 44 セクション波動管、摩擦ノイズは明示的な前後腔フィルタへ分離するハイブリッド方式へ切り替えた。

これは有用な否定結果である。単一の物理モデルへすべてを押し込むより、役割ごとに適切な近似を組み合わせる方が、音素差と制御性を保ちやすいことが示された。

`/sa/`、`/ɕi/`、`/ɸu/` の CV 合成も生成されたが、実録音とのスペクトログラム重ね合わせや比較 CLI による評価は未実施である。Reynolds 数閾値、ノイズ強度則、前後腔長も教育的な簡略モデルであり、実測による校正値ではない。

成熟度: B。生成と診断は成立し、ハイブリッド化という設計知見を得たが、音声学的妥当性は未検証である。

### 4.6 流体力学、LBM、非周期性

文献調査では、Lighthill 音響アナロジー、単極・双極・四重極音源、声門ジェット、Coanda 効果、LES、DNS、LBM、流体構造連成、管楽器との類比を整理した。

`fluid-dynamics-intro.ipynb` では次の概念実証を行った。

- 断面積と流速から声道内の Reynolds 数を可視化
- 音源強度の速度依存性を比較
- 開口率に応じた aspiration noise による声質変化
- 確率的なジェット偏向による jitter / shimmer の付与
- D1Q3 LBM と 1D DWM のインパルス応答比較

Notebook 内のモデルでは、`/s/` の最大 Re 4343、`/a/` の最大 Re 1434、Coanda 確率 0.0〜0.6 に対して jitter 0.27%〜0.79%、shimmer 0.00%〜10.78% などが得られた。

これらは実験データから推定した値ではなく、設定した簡略式から得られたシミュレーション出力である。特に確率的 Coanda モデルは、自然な非周期性を作る手続きとしては有用だが、Coanda 効果がその jitter / shimmer を定量的に説明したことにはならない。Lighthill の速度スケーリングも、音圧、音響強度、音響パワーの区別を含めて原典に戻った式の監査が必要である。

成熟度: B から D が混在。可聴化された教材・仮説生成環境として価値があるが、物理モデルとして利用する前に式、単位、境界条件、文献解釈の再検証が必要である。

### 4.7 2D Digital Waveguide Mesh

研究側には、矩形格子、形状生成、音源、散乱ソルバー、解析、WAV 出力を分離した DWM 実装がある。直管、簡易 `/a/`、簡易 `/i/`、インパルス、パルス列、簡易グロッタル音源、口端の pressure / flow / radiated 観測を試している。

ソルバーが動作し、形状別の応答と WAV を生成できたことは確認できる。しかし初期インパルス応答の主要ピークは 10〜22 kHz 付近へ偏り、格子を細かくしても 6〜11 kHz 付近に現れた。持続励振時に得られた 116、358、483、600、716 Hz などのピーク列には、声道共鳴だけでなく音源の倍音が混入している可能性が高い。

`radiated` 出力と 1200 Hz 前後の放射 cutoff を用いると `/a/` と `/i/` の最初の検出ピークに差が現れたが、これを母音フォルマントの再現とみなす根拠はまだ弱い。直管の解析解、1D 管モデル、格子収束、数値分散、境界反射、観測量の定義を揃えた検証が先に必要である。

成熟度: C。実験基盤としては成立しているが、音響モデルとしての成功条件は未達または未判定である。

### 4.8 2D FDTD Web プロトタイプ

`acoustic-fdtd-2d` は、staggered grid 上の `p`、`vx`、`vy` を更新し、音源、耳、反射、吸音、透過、散乱、周波数依存壁を Canvas 上で操作できる。耳セルの記録を Web Audio で再生できる。

このプロトタイプは、波の伝搬、反射、減衰を視覚的に理解する用途では成功している。一方、実装文書自身が明記しているように、物理単位より表示と安定性を優先した正規化モデルであり、画面ステップと音声サンプルレートも一致していない。壁材料も厳密なインピーダンス境界ではない。

したがって、これは現在のところ発声合成器ではなく、2D 波動現象と UI の実験台である。声道形状、声門音源、口唇放射、固定 `dx/dt`、PML、リサンプリングを導入して初めて、声道音響の検証系へ進める。

成熟度: C。対話的可視化として成立、物理的・音声的な校正は未実施である。

## 5. UTAU リファレンス音声解析

現時点で最も体系的かつ再現可能な研究成果である。UTAU 音源は合成素材ではなく、人間音声の参照値と評価データとして使われた。

### 5.1 台帳化

5,704 件の WAV を読み込み、すべて 44.1 kHz、mono として台帳化した。

| 分類 | 件数 |
| --- | ---: |
| CV | 2,763 |
| VCV | 2,588 |
| breath | 198 |
| vowel | 90 |
| unknown | 54 |
| dialogue | 11 |

40 個の `oto.ini` から 17,298 行を UTF-8 CSV 化した。日本語ファイル名、CP932、`.frq`、複数 alias など、実データ特有の処理を実装できた点も成果である。

### 5.2 母音フォルマント

5 母音各 18 件、計 90 件を LPC で解析した中央値は次のとおりである。

| 母音 | F1 Hz | F2 Hz | F3 Hz |
| --- | ---: | ---: | ---: |
| `/a/` | 961.666 | 1396.077 | 2378.362 |
| `/i/` | 376.027 | 2830.672 | 3724.615 |
| `/u/` | 498.038 | 1326.122 | 1764.349 |
| `/e/` | 664.538 | 2354.347 | 3269.838 |
| `/o/` | 717.165 | 1041.377 | 3171.097 |

F1 は 28 件、F2 は 13 件、F3 は 7 件が欠損した。高い F0、息成分、短い区間、録音条件の違いが LPC を不安定にすることが確認された。

得られた値は有用な候補だが、日本語母音の一般的な正解値ではない。対象が UTAU 用の持続発声であり、話者構成、歌唱用収録、F0、マイク、音源制作時の処理に依存するためである。

### 5.3 話者スケール

12 の話者・音源プリセット候補について、Web 実装の `tractScale` は 0.925170〜1.061705 に収まった。多くが 1.0 近傍だったため、声道スケールは大きな音色変化の主パラメータではなく、話者プリセットの微調整値として扱うという判断につながった。

ただし、これはフォルマント倍率の逆数を単一スカラーに縮約した近似である。話者差は声道長だけでなく、各部の形状、F0、声門音源、発話様式にも依存するため、単一 `tractScale` が話者モデルを表すわけではない。

### 5.4 声質

90 件の母音について、スペクトル重心、高域比、スペクトル傾斜、倍音減衰、非周期エネルギー近似、F0/RMS 安定性を計算した。

音源名に含まれる `vivid`、`Dark`、`Boyish` などは、音源内比較では傾向が見えることがある一方、音源横断で一貫した音響ラベルにはならなかった。この結果から、声質名ではなく測定量を基準に `brightness` と `breathiness` を設計する方針が得られた。

ただし H1-H2、HNR、CPP、逆フィルタリング、EGG など、声門音源と声質をより直接表す指標は未導入である。現在の `nonharmonic_energy_ratio` も簡易近似である。

### 5.5 母音遷移

7,241 件の VCV alias から 25 種類の母音ペアを抽出し、`preutterance - overlap` の中央値 166.667 ms、平均 175.511 ms を得た。この値は Web プロトタイプの母音補間時間へ反映された。

ここで測定したのは UTAU の原音設定タイミングであり、実際の F1/F2/F3 軌跡ではない。166.667 ms は実装初期値として根拠を持つが、人間の母音遷移時間を直接測定した値とはいえない。

### 5.6 子音・息・ノイズ

237 件を解析し、sibilant 90、`h` 系摩擦音 90、bonus 38、breath 11、consonant 8 に分類した。

代表値として、`し` のスペクトル重心 5631 Hz、高域比 0.773、`す` の重心 5642 Hz、息の重心 3404 Hz が得られた。これを根拠に、Web では 6 kHz 前後の bandpass ノイズによる `し/す`、3.4 kHz 前後の highpass ノイズによる breathiness を試作した。

`さ/せ/そ` の先頭区間には母音成分が混ざりやすく、`し/す` の方が初期ノイズモデルとして分離しやすいという実装上の知見も得られた。

一方、UTAU の CV サンプル先頭 180 ms を一律に切り出す方式は、音素境界を厳密に揃えた解析ではない。今後は `oto.ini`、forced alignment、短時間スペクトルを組み合わせ、子音の定常部と遷移部を分ける必要がある。

### 5.7 UTAU 解析の総合評価

成熟度: A。ただし「パイプラインが再現可能」という意味であり、「測定値が一般化された人間音声の基準値」という意味ではない。

強みは、台帳、抽出、集計、Web 向け JSON/TypeScript 出力まで自動化されている点である。弱みは、単一種別の音声資源、日本語中心、持続音・歌声ライブラリ中心、録音条件の不統一、自動 LPC の欠損である。

## 6. 比較ツールと反復調整

### 6.1 比較基盤

`audio_utils.py`、`compare_waveforms.py`、`compare_waveform_pairs.py` により、次の指標を CSV、JSON、PNG へ出力できる。

- 波形 RMSE、正規化相互相関、SNR
- log spectral distance、spectral convergence
- F0 と cents 差
- LPC フォルマントと MAE
- スペクトル重心、傾斜、帯域比、peak、flatness
- フレーム単位スペクトル距離と簡易 DTW
- onset、stable、RMS rise time
- 単一ペアと複数ペアの集計

母音、ノイズ、遷移の各モードで自己比較を行い、距離 0、相関 1 になることを確認している。これは実装のスモークテストとして有用である。

ただし自己比較は、正しい答えを返す最低条件しか保証しない。既知の時間ずれ、F0 差、振幅差、フォルマント差、ノイズ帯域差を人工的に与え、期待方向と大きさを検証する単体テストはない。

### 6.2 `/a/` の反復実験

`maoto/単独音/あ.wav` を参照し、10 回の反復生成を行った。

| 指標 | 初期 | 改善版最終 |
| --- | ---: | ---: |
| 複合スコア | 88.669039 | 48.588397 |
| log spectral distance | 73.054717 dB | 42.877531 dB |
| spectral convergence | 1.102948 | 0.436571 |
| formant MAE | 396.535406 Hz | 44.510082 Hz |
| normalized cross-correlation | 0.249916 | 0.519529 |
| F0 差 | -13.578376 cents | 0 cents |

複合スコアは 45.20% 改善した。F1/F3 とゲインの一部は `tuned` `/a/` プリセットへ反映された。

これは、このリポジトリで最も明確な「測定、生成、比較、調整、実装反映」の閉ループである。同時に限界も明確である。

- 対象は 1 話者、1 サンプル、1 母音のみ
- 調整規則は手作業的で、一般的な最適化器ではない
- `spectral_match` は参照スペクトル包絡を直接混ぜる上限確認であり、最終方式には採用できない
- 最良スコアが知覚上もっとも自然とは限らない
- 同じサンプルへの適合であり、別録音・別話者への汎化は未評価

`spectral_match` をそのまま実装せず、source tilt、フォルマントゲイン、帯域別ゲインなど、説明可能なパラメータへ分解するという判断は、新しいプロジェクト方針にも整合する。

成熟度: A。実験自体は成立しているが、結論の一般化可能性は低い。

## 7. 研究結果から Web 実装への接続

第1 Web プロトタイプには次が反映された。

- `reference` / `utau` / `tuned` の母音プリセット切り替え
- UTAU 由来の話者 `tractScale`
- 166 ms の母音補間
- `brightness` / `breathiness`
- 6 kHz 前後の `し/す` ノイズ
- `し/す + 母音` の簡易音素イベント
- 0〜4 kHz のリアルタイムスペクトルと F1/F2/F3 マーカー

これにより、研究結果を数値ファイルに留めず、聴覚・視覚の両方で確認できるようになった。

しかし、試聴記録にはビルドと表示確認が 1 件記録されているだけで、体系的な聴感評価はない。また Web 側で生成音を WAV 保存する経路がないため、`し/す + 母音` を比較 CLI の transition モードへ戻せていない。研究から Web への一方向接続はできたが、Web から評価系へ戻る経路が未完成である。

## 8. 調査から見えてきた方向性

文献調査では、次の構図が一貫して現れた。

### 8.1 単一モデルですべてを解くのは現実的でない

母音の声道共鳴、声門の周期音源、摩擦音の乱流、鼻腔分岐、放射、調音運動では、適切なモデルの粒度が異なる。摩擦音 Phase 3 で直接注入方式が失敗し、明示フィルタと波動管のハイブリッドへ移った経験も、この判断を支持する。

### 8.2 軽量な生成系と高忠実度な検証系を分けるべきである

1D 管、伝送線路、フォルマントフィルタ、手続き的ノイズは、制御と反復に向く。FDTD、FEM、LBM、CFD、FSI は、検証や局所現象の理解に向く。高忠実度モデルをそのまま最終生成器にする必要はなく、軽量モデルの近似誤差を調べる基準として使う方が現実的である。

### 8.3 物理性より「明示的で検証可能な生成機構」が共通軸になる

現行資産には、物理モデル、経験的フィルタ、規則ベースイベント、データから抽出したパラメータ、数値最適化が混在する。新しい方針では、これらを物理的か否かだけで分けず、音源が明示的で、制御でき、参照音声を再生せず、生成過程を検証できるかで評価できる。

この軸なら、既存成果を捨てずに、方式選択の自由度を上げられる。

## 9. 現在の強み

### 9.1 調査と実装の距離が短い

文献で得た概念が Notebook、スクリプト、Web UI へ比較的早く移されている。声門音源、乱流ノイズ、遷移時間、フォルマント、話者スケールがその例である。

### 9.2 観察可能性を重視している

波形、スペクトル、スペクトログラム、声道形状、2D 波動場、F1/F2/F3 マーカーを用意しており、内部状態を隠したまま音だけを出す構成ではない。

### 9.3 失敗を次の設計へつなげている

第2波動管の瞬時伝搬、摩擦音の過減衰、DWM の高域偏重、LPC 欠損、声質ラベルの不一致など、期待どおりでなかった結果が記録され、次の方式変更へ使われている。

### 9.4 参照音声を素材ではなく測定対象として扱っている

UTAU 音声からフォルマントやタイミングを抽出しているが、波形断片を最終合成へ接続していない。これは現在のプロジェクト境界とよく一致する。

### 9.5 評価基盤の芽がある

比較 CLI と反復実験により、聴感だけに頼らず変更を追跡する基盤ができた。この基盤を一般化すれば、今後の方式比較の中心になりうる。

## 10. 偏りと不足

### 10.1 音声データの偏り

- 日本語 UTAU 音源に集中している
- 持続母音、CV、VCV が中心で、自然会話ではない
- 歌唱・音源制作向けの録音条件や加工の影響を受ける
- 1.4 GB のデータ量はあるが、独立した話者数は 12 程度である
- 年齢、性別、方言、発話様式、収録機器のバランスを設計していない
- 自前録音領域は実質的に未使用である

データ件数の多さに比べ、母集団の多様性は狭い。

### 10.2 音素範囲の偏り

- 母音研究が圧倒的に多い
- 子音は `し/す`、`/s/ /ʃ/ /f/` 系に偏る
- 鼻音、破裂音、破擦音、接近音、弾き音、無音閉鎖、VOT はほぼ未着手
- 長い音素列、アクセント、イントネーション、リズム、発話速度を扱っていない
- 調音運動と共調音は固定補間に留まる

現状は「声」より「母音を中心とした発声要素」の研究に近い。

### 10.3 評価の偏り

- 自動指標は増えたが、知覚評価がほぼない
- 反復調整は `/a/` 1 例のみ
- 同一参照への適合で、hold-out データがない
- 自己比較テストはあるが、既知変形に対する指標の感度テストがない
- 指標を合成した複合スコアの重みが、知覚的重要度に校正されていない
- 「母音として認識されるか」「自然か」「同じ話者に感じるか」を分離していない

数値改善と人間の知覚改善が対応するかは未確認である。

### 10.4 物理検証の不足

- 1D 管モデルの均一管以外の解析解比較がない
- DWM の格子収束、数値分散、境界条件の検証がない
- FDTD は物理単位へ校正されていない
- 声道断面積と目標フォルマントの対応表がない
- 声門音源を EGG や推定グロッタルフローと比較していない
- 摩擦音モデルを実録音の PSD、音源位置、流量と比較していない
- 流体 Notebook の式と単位を原典に沿って監査していない

物理モデルの数は増えたが、共通ベンチマークがないため、どのモデルがどの現象をどの精度で再現するか比較できない。

### 10.5 実装と文書のずれ

- `waveguide-vocal-tract` の計画は完全 LF と LPC を述べるが、実装は簡略 LF と FFT ピークである
- トロンボーン検証本文の誤差範囲と保存された数値表が一致しない
- Notebook のまとめには、可聴デモで確認した所感と定量的事実が混在する
- 一部文書には移動前の `docs/notes/` パスが残る
- `research/data/generated/` と `research/data/raw/generated/` が併存する

総括時には、計画、実装、実行結果を別の列で管理する必要がある。

### 10.6 再現性と保守性

- `requirements.txt` は下限指定のみで、ロックファイルがない
- Python の自動テストがない
- Web にも単体テストや音響回帰テストがない
- 既存 UTAU スクリプトには、後から追加した `audio_utils.py` と重複する処理が多い
- 5 つの UTAU 可視化 Notebook は実行結果を保存していない
- 生成物の Git 管理基準がまだ一貫していない
- 元 UTAU 音声は Git 管理外で、再取得手順と完全なライセンス台帳が十分ではない
- Notebook 出力にはローカル絶対パスやフォント警告が残る

現在の環境では再実行できても、別環境や将来時点で同じ結果になる保証は弱い。

### 10.7 方式探索の偏り

物理音響、波動管、流体力学の調査は厚い。一方、現在の新方針で許容される次の領域は薄い。

- 規則ベースの音素ジェスチャー記述
- 調音スコアや gestural model
- 制約付き最適化、ベイズ最適化、微分可能 DSP
- 物理パラメータの同定と不確実性推定
- 聴覚モデルを用いた知覚距離
- 明示パラメータを持つ低次元統計モデル
- 音素列、韻律、発話計画の制御モデル

物理に限定しない方針へ変わったため、今後は「音を直接生成する大規模 AI」以外の制御・最適化手法も比較対象にできる。

## 11. 不足を補うための提案

### 11.1 最優先: 共通ベンチマークを定義する

新しい方式を増やす前に、すべてのモデルを同じ入力・出力・指標で比較できる最小ベンチマークを作る。

推奨する最初の課題は次の 4 つである。

1. 均一な閉端・開端管のインパルス応答
2. 既知の断面積列 5 種の F1/F2/F3
3. 5 母音の 1 秒持続音
4. `し/す + 母音` の 1 音節イベント

各モデルは WAV、パラメータ JSON、計算時間、スペクトル、主要指標を同じ形式で出力する。解析解、文献値、参照音声、知覚評価のどれと比較するかも課題ごとに固定する。

### 11.2 `/a/` の閉ループを 5 母音と hold-out へ広げる

`iterate_vowel_match.py` を母音汎用にし、まず 5 母音すべてで同じ反復を行う。ただし 1 サンプルへ適合して終わらせず、次の分割を使う。

- 調整用話者・サンプル
- 検証用の同話者別テイク
- 検証用の別話者

最適化対象は、フォルマント、帯域幅、ゲイン、source tilt、ノイズ量など説明可能なパラメータに限定する。`spectral_match` は上限比較としてのみ残す。

### 11.3 オフライン生成 CLI を研究の中心に置く

Web Audio の内部状態を直接評価するのではなく、同じ合成モデルをオフラインで決定論的に実行し、WAV とメタデータを出せる CLI を作る。

これにより次が可能になる。

- Web と研究側で同じパラメータを使う
- 子音遷移を比較 CLI へ戻す
- seed を固定したノイズ比較
- CI で短い音響回帰テスト
- 実験ごとの完全な再生成

Web は、その CLI または共通コアのパラメータを操作する試聴・観察面として位置づける。

### 11.4 物理モデルを段階的に検証する

DWM や FDTD を母音形状へ進める前に、次の順序で検証する。

1. 均一管の共鳴周波数と減衰時間
2. 2 セクション管の反射・透過係数
3. 既知の段付き管の伝達関数
4. 1D 波動管と 2D DWM/FDTD の比較
5. 格子幅を変えた収束と数値分散
6. 口端放射と壁損失の感度分析
7. 最後に母音形状

これにより、「母音らしくない原因」が形状、音源、境界、観測方法、数値誤差のどこにあるか分離できる。

### 11.5 声門音源を実測へ接続する

Rosenberg、LF、簡略 LF、将来の 2-mass モデルを、同じ F0、RMS、声道フィルタで比較する。可能なら公開 EGG またはグロッタルフロー推定データを用い、次を測る。

- open quotient
- speed quotient
- H1-H2
- spectral tilt
- normalized amplitude quotient
- CPP / HNR

「自然に聞こえる」という単一評価ではなく、パラメータがどの声質軸を制御するかを確認する。

### 11.6 子音研究をイベント単位へ進める

次の短期対象は、すでに資産がある `し/す + 母音` が妥当である。

- オフラインで同じ音素イベントを生成する
- `oto.ini` だけでなく実波形からノイズ開始、母音 onset、スペクトル重心軌跡を測る
- bandpass 中心、Q、エンベロープ、overlap、母音立ち上がりを最適化する
- 別話者で検証する

その後、閉鎖を追加すれば破擦音・破裂音へ、鼻腔分岐を追加すれば鼻音へ進める。

### 11.7 知覚評価を小さく始める

大規模な被験者実験の前に、再現可能な少人数評価を設計する。

評価軸を分離する。

- どの母音・音節に聞こえるか
- 自然さ
- 明瞭さ
- 息っぽさ、明るさなど意図した声質
- A/B のどちらが参照へ近いか

ランダム化、音量正規化、ブラインド化、評価条件、回答数を記録する。自動指標との相関も確認する。

### 11.8 リファレンスを多様化する

UTAU は継続利用しつつ、役割の異なる小規模データを加える。

- 自前収録した 5 母音と CV 音節
- 自然発話の公開コーパスから、権利条件が明確な短区間
- 声質または EGG を含む公開音声データ
- 解析解を持つ人工管・物理模型のインパルス応答
- 条件を明記した生成 AI 音声を、必要なテストケースの補助リファレンスとして使用

重要なのは件数ではなく、各データがどの仮説を検証するかを明確にすることである。

### 11.9 研究基盤を整理する

- 新しい研究は `research/experiments/<name>/` に置く
- 各実験に仮説、入力、実行方法、結果、採否を書く
- Python 依存関係を lock または環境情報付きで固定する
- `audio_utils.py` へ重複処理を統合する
- 既知変形を使った単体テストを追加する
- 重要な CSV と最終図だけを Git 管理する
- `data/generated/` と `data/raw/generated/` を段階的に統一する
- 計画文書に `planned / implemented / validated` の状態を付ける
- 文献メモの DOI、書誌情報、主張と出典の対応を監査する

## 12. 推奨する研究ロードマップ

### フェーズ A: 評価系を固める

1. 共通ベンチマーク仕様を作る
2. オフライン生成 CLI を作る
3. 比較指標の既知変形テストを作る
4. `/a/` 実験を 5 母音と hold-out へ広げる
5. 小規模知覚評価を行う

このフェーズの目的は、方式を選べる測定器を作ることである。

### フェーズ B: 明示的な発声モデルを統合する

1. 声門音源を Rosenberg / LF 系で整理する
2. 母音の source-filter 基準系を確立する
3. `し/す + 母音` のイベントモデルを評価する
4. brightness / breathiness を音響指標へ校正する
5. 形状ベース声道モデルを同じベンチマークで比較する

このフェーズの目的は、完全な物理モデルではなく、母音、声質、最初の子音を説明可能なパラメータで生成することである。

### フェーズ C: 形状・物理モデルを検証系として強化する

1. 1D 管モデルの解析解検証
2. 2D DWM/FDTD の格子収束と境界検証
3. 声道形状とフォルマントの逆問題
4. 鼻腔分岐、側枝、放射インピーダンス
5. 準 1D 流れとパラメトリック・ノイズ源
6. 必要な局所だけ LBM/FEM/CFD で検証

このフェーズの目的は、高忠実度計算を最終生成器へ直結することではなく、軽量モデルがどこまで正しいかを説明できるようにすることである。

### フェーズ D: 発話へ拡張する

1. 調音ジェスチャーと共調音
2. 破裂音、鼻音、接近音
3. 音素列と状態遷移
4. F0、強度、継続時間による韻律
5. 話者プリセットと声質プリセット
6. 長い発話での安定性と操作 UI

## 13. 現時点での判断

今後ただちに新しい高忠実度モデルを増やすより、既存の研究資産を共通ベンチマークとオフライン生成経路へ接続する方が効果が高い。

短期の主線としては、次の構成が最も現実的である。

```text
明示的な声門音源
    +
フォルマントまたは検証済み 1D 声道モデル
    +
形状・音素イベントに応じた局所ノイズ源
    +
規則ベースの時間制御
    ↓
オフライン生成
    ↓
音響指標 + 知覚評価
    ↓
Web で試聴・観察
```

DWM、FDTD、LBM、FEM などは捨てるのではなく、この軽量系の近似を検証し、必要な現象を発見する研究系として並行させる。

この構成は、物理を選択肢として維持しながら、人間の発声へ近づくために説明可能な手法を組み合わせるという現在の方針に合う。また、録音音声や大規模学習済み生成モデルを最終音源にせず、参照音声を測定と評価へ限定する境界も保てる。

## 14. 結論

これまでの研究は散漫に見える部分もあるが、完全に無関係な試行の集合ではない。実際には、次の問いを異なる角度から調べてきた経緯とみなせる。

> 声らしさを構成する音源、共鳴、ノイズ、時間変化、形状を、どの粒度なら明示的に制御し、観察し、検証できるか。

UTAU 解析と `/a/` 反復実験は、参照音声から説明可能なパラメータを得て実装へ戻す方法を示した。声門・摩擦音 Notebook は、周期音源とノイズ音源を分けて制御する可能性を示した。波動管、DWM、FDTD は、形状と伝搬を扱うための複数の忠実度レベルを用意した。

不足しているのは、さらに多くの方式ではなく、同じ問いに対して方式間を比較する基準、別データへの一般化、知覚評価、実装と文書の状態管理である。

次の段階では、研究量を増やすことより、既存成果を「再現できる」「比較できる」「採否を決められる」形へ変えることが重要である。それができれば、このリポジトリは単なる音声実験集から、明示的・制御可能な発声生成系を体系的に構築する研究基盤へ発展できる。
